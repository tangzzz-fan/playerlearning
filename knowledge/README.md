# knowledge/ · 原理与基础

> **这套文档回答的不是"某个阶段做完了什么"（那在 `docs/`），而是"这套系统是什么、怎么运转、为什么这样设计"。**
> 从最基础的概念讲起 —— 不假设你懂媒体或图形领域。

## 为什么单独一个目录

| 目录 | 语义 | 回答的问题 |
| --- | --- | --- |
| `docs/` | **阶段交付物**（编号 = 阶段） | "做过什么？证据在哪个文件？" |
| `knowledge/`（本目录） | **原理与基础** | "为什么是这样？它到底怎么运转？" |

`docs/` 的编号是"阶段"语义（`docs/03` = 路线图，`docs/NN` = 某阶段验证报告）。
教学材料混进去会破坏"编号 = 阶段"这条语义 ⇒ 独立成 `knowledge/`。

**两个目录的关系**：本目录里每一条结论，都能在 `docs/` 里找到可核对的实测记录；
本目录负责把那些散落的碎片组织成**一条能读通的线**。

## 读写约定（每一篇都遵守）

1. **结论先说** —— 开头一段粗体直接给答案，不铺垫。
2. **证据可核对** —— 关键论断给出"怎么自己验一遍"（命令 + 预期输出）。
3. **术语就地解释** —— 外文术语首次出现给中英对照；篇尾有术语表。
4. **拿不到证据就标"未验证"** —— 不写成结论。
5. **图分两种**：结构关系用 **mermaid**（文本易改）；成品示意图（数据流 / 时间线 / 构建管线）用
   `assets/` 下的 **SVG**（布局可控、不依赖渲染器的 mermaid 支持）。

## 三条阅读路线

| 你的目的 | 读这几篇 | 为什么 |
| --- | --- | --- |
| 只想搞懂"这套系统是什么" | **K1 → K8 → K3** | 概念底 → 格式是怎么被认出来的 → 一帧像素的旅程 |
| 要改配方 / 换 mpv 版本 / 从零搭环境 | **K1 → K2 → K7** | K2 是产物的生产线 |
| 要做网络点播 / 直播 / 在别的视频源上做处理 | **K1 → K3 → K4 → K5 → K6** | 后三篇是网络与图形 |
