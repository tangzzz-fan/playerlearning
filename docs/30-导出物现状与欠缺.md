# 30 · 导出物（对外可消费形态）现状与欠缺

> 本文回答一个问题：**「今天这个项目，能不能作为一个东西交给别的项目用？」**
>
> 结论全部来自**当场跑出来的输出**，不是从清单推断的。每条都附命令，你可原地复核。
>
> 与 [`docs/29`](29-移植到JoveView-方案.md) 的关系：29 讲「怎么搬」，本文讲「**搬的前提——包本身能不能被别人引**」。
>
> **状态**：2026-10-17 按方案乙开工，`v0.1.0` 已发布。剩余唯一未通的是**仓库可见性**（见 §八）。

---

## 一、结论

**分两个阶段看，不是一个答案。**

| 阶段 | 外部项目怎么引 | 能不能构建 |
| --- | --- | --- |
| **现在（仓库 private）** | `path:` 指向**仓库根**（`PlayerMPV` 已并入根清单） | ✅ 可以 |
| **开源之后** | `url:` + `from: "0.1.0"` | ✅ 会通（`v0.1.0` 的 Release 资产已就位，`URL` 与 `checksum` 都不用改） |
| 现在就用 `url:` | —— | ❌ `badResponseStatusCode(404)`（private 资产匿名拿不到） |

**为什么两种形态的差别只有一行**：`binaryTarget` 的 url 指向一个固定 tag 的资产，
开源那一刻同一个 URL 从 404 变 200 —— **不需要重新打包、不需要改 checksum**。
所以私有期清单保持 `path:`（否则本机自己就构建不了），开源时把那一行换掉即可（§八）。

### 四种消费方式（现状）

| 消费方式 | 能否工作 | 依据 |
| --- | --- | --- |
| `path:` → 仓库**根**（本机，任意项目） | **✅ 可以** | 外部消费者 + iOS 构建 `BUILD SUCCEEDED`（§二证据 5） |
| `path:` → `MPV/` 子目录 | ✅ 仍可用，但**不再需要** | 子包清单已删除 |
| `path:` → **干净 clone** | ❌ | `local binary target 'Libmpv' … does not contain a binary artifact` |
| `url:` + tag | ❌（仅因 private） | `badResponseStatusCode(404)` |
| CocoaPods / 手工拖 xcframework | ❌ | 无 `podspec`；无对外发布产物 |

## 二、实测证据（输出原文）

### 证据 1 · 干净 clone 里没有产物目录（**未变**）

```bash
git clone /Users/tango/Developments/playerlearning /tmp/pl-clean
ls -d /tmp/pl-clean/MPV/Library
# ls: /tmp/pl-clean/MPV/Library: No such file or directory
```

原因：`.gitignore:19` → `MPV/Library/*.xcframework/`；`git ls-files MPV/Library` 输出 **0 行**。

### 证据 2 · 干净 clone 上构建必然失败（**未变**）

```bash
cd /tmp/pl-clean/MPV && swift build --disable-sandbox
# error: local binary target 'Libmpv' at '…/MPV/Library/Libmpv.xcframework'
#        does not contain a binary artifact.
```

> 这条只有在**清单写着 `path:`** 时成立。开源后清单换成 `url:`，同一场景变成"下载 40 MB"。

### 证据 3 · 依赖仓库根拿不到适配器（**已修复**）

```bash
# 修复前：根清单没有 PlayerMPV product
swift build --disable-sandbox
# error: product 'PlayerMPV' required by package 'consumera' target 'ConsumerA'
#        not found in package 'playerlearning'.
```

修复：`b8398c3` 把 `PlayerMPV` 并入根 `Package.swift`（target path 指向 `MPV/Sources/PlayerMPV`），
并删除 `MPV/Package.swift`（留着会出现两个 package identity）。

### 证据 4 · 外部消费者现在能 import（**修复后实测**）

```bash
# 消费方：.package(path: "…/playerlearning") + .product(name: "PlayerMPV", package: "playerlearning")
xcodebuild -scheme ConsumerC -destination 'generic/platform=iOS' \
  OTHER_SWIFT_FLAGS=-disable-sandbox build
# ** BUILD SUCCEEDED **
```

同一份代码用 `import PlayerCore` + `import PlayerMPV` 都能过。**A1 关闭。**

### 证据 5 · `url:` 形态卡在仓库可见性（**本轮新增**）

在临时副本里把 `binaryTarget` 换成 `url:` + checksum，跑构建：

```bash
swift build --disable-sandbox
# Downloading binary artifact https://github.com/tangzzz-fan/playerlearning/releases/download/v0.1.0/Libmpv.xcframework.zip
# [100/100] Downloading … (9 bytes / 9 bytes)
# error: failed downloading '…/Libmpv.xcframework.zip' which is required by binary target
#        'Libmpv': badResponseStatusCode(404)
```

```bash
# 同一 URL 匿名访问
curl -sS -o /dev/null -w "HTTP %{http_code}\n" -L "$URL"
# HTTP 404
```

⇒ **SwiftPM 不会带 git 凭据去下 binaryTarget。** private 仓的 Release 资产，SPM 拿不到。

## 四、两个必须知道的坑

### 4.1 `package:` 参数认的是**目录名**（identity），不是清单里的 `name`

```swift
// 实测报错
error: unknown package 'PlayerStack' in dependencies of target …
       valid packages are: 'playerlearning' (at '/Users/tango/Developments/playerlearning')
```

⇒ 消费方必须写 `.product(name: "PlayerMPV", package: "playerlearning")`。

**换成 `url:` 之后 identity 还是仓库名 `playerlearning`** —— 这一点不会因为形态改变而变。
（`path:` 与 `url:` 都用仓库目录名做 identity，所以这次切换**不需要**改 `package:` 参数。）

### 4.2 macOS 上是「编译得过、里面是空的」

```bash
/usr/libexec/PlistBuddy -c "Print :AvailableLibraries" …/Info.plist
# SupportedPlatform = ios            ← ios-arm64
# SupportedPlatform = ios (simulator) ← ios-arm64_x86_64-simulator
# （没有 macos）
```

| 环 | 事实 |
| --- | --- |
| ① | `Libmpv` 用 `.when(platforms: [.iOS])` ⇒ macOS 不引入 |
| ② | `MPVKernel.swift` **整份文件**（L1–L956）被 `#if canImport(Libmpv)` 包住 |
| ③ | macOS 上 `canImport(Libmpv)` 为 false ⇒ **整个适配器被编译掉** |

**结果不是"崩"，而是"空模块"**：`import PlayerMPV` 能过，但里面一个类型都没有。
⇒ `platforms:` 里的 `.macOS` 目前是**空头支票**；判据必须是 iOS 目标构建（`P-096`）。

**本轮已补验**：`xcodebuild -scheme PlayerMPV -destination 'generic/platform=iOS Simulator'` ⇒
`BUILD SUCCEEDED`（模拟器 slice 存在且可链接）。

## 八、开源那一刻要改的三行

清单里把这一行：

```swift
.binaryTarget(name: "Libmpv", path: "MPV/Library/Libmpv.xcframework")
```

换成：

```swift
.binaryTarget(
    name: "Libmpv",
    url: "https://github.com/tangzzz-fan/playerlearning/releases/download/v0.1.0/Libmpv.xcframework.zip",
    checksum: "f98a0c3fa47f0a7cc7cb1c2d8160c892c3e584da478862dfa05a3c082caca0d6"
)
```

**不需要改**：`package:` 引用（identity 仍是 `playerlearning`）、product 名、target path、Demo 配置。

改完按这三条验证（缺一步都不算完成）：

```bash
# 1. 干净 clone（不带本机 .build 缓存）
git clone <url> /tmp/pl-verify && cd /tmp/pl-verify
# 2. 求值清单：确认 url 形态生效
swift package dump-package --disable-sandbox | grep -A3 Libmpv
# 3. iOS 目标构建（必须 iOS，macOS 是空模块，P-096）
xcodebuild -scheme PlayerMPV -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/dd-verify OTHER_SWIFT_FLAGS=-disable-sandbox build
```

**注意**：`v0.1.0` 这个 tag 上的**清单仍是 `path:` 形态**。
用 `url:` 引用 `v0.1.0` 的消费者读到的还是那份 `path:` 清单 ⇒ 会失败。
所以开源切换必须**再打一个 tag**（如 `v0.1.0-r2` 或直接 `v0.2.0`），不能只改 main。
