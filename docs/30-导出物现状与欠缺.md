# 30 · 导出物（对外可消费形态）现状与欠缺

> 本文回答一个问题：**「今天这个项目，能不能作为一个东西交给别的项目用？」**
>
> 结论全部来自**当场跑出来的输出**，不是从清单推断的。每条都附命令，你可原地复核。
>
> 与 [`docs/29`](29-移植到JoveView-方案.md) 的关系：29 讲「怎么搬」，本文讲「**搬的前提——包本身能不能被别人引**」。

---

## 一、结论

**今天能「用」，但只有一种姿势：在同一台机器上，用 `path:` 指向 `MPV/` 子目录。**

换任何人、任何机器、任何 `url:` 引用，都拿不到能构建的东西。

| 消费方式 | 能否工作 | 实测依据 |
| --- | --- | --- |
| `path:` → `MPV/` 子目录（本机） | **✅ 可以** | iOS 目标 `BUILD SUCCEEDED`（macOS 那次 `swift build` 是空模块，不算，见 §4.2） |
| `path:` → 仓库**根** | ❌ | `product 'PlayerMPV' … not found in package 'playerlearning'` |
| `path:` → **干净 clone** | ❌ | `local binary target 'Libmpv' … does not contain a binary artifact` |
| `url:` + tag | ❌ | 根清单没有 `PlayerMPV` product；`git tag` 为 0；无发布 zip |
| CocoaPods / 手工拖 xcframework | ❌ | 无 `podspec`；无对外发布产物 |

---

## 二、四条实测证据（输出原文）

### 证据 1 · 干净 clone 里根本没有产物目录

```bash
git clone /Users/tango/Developments/playerlearning /tmp/pl-clean
ls -d /tmp/pl-clean/MPV/Library
# ls: /tmp/pl-clean/MPV/Library: No such file or directory
```

原因：`.gitignore:19` → `MPV/Library/*.xcframework/`；`git ls-files MPV/Library` 输出 **0 行**。

### 证据 2 · 干净 clone 上构建必然失败

```bash
cd /tmp/pl-clean/MPV && swift build --disable-sandbox
# error: local binary target 'Libmpv' at '…/MPV/Library/Libmpv.xcframework'
#        does not contain a binary artifact.
```

### 证据 3 · 依赖仓库根，拿不到适配器

```bash
# 消费方 Package.swift：.package(path: "…/playerlearning")
swift build --disable-sandbox
# error: product 'PlayerMPV' required by package 'consumera' target 'ConsumerA'
#        not found in package 'playerlearning'.
```

原因：根 `Package.swift` 只声明了两个 product —— `PlayerCore`、`PlayerUI`。
`PlayerMPV` 是 `MPV/Package.swift` 里独立的一个包。

### 证据 4 · 依赖 `MPV/` 子目录，能构建（但只在 iOS 上真的用到二进制）

```bash
# 消费方 Package.swift：.package(path: "…/playerlearning/MPV")
swift build --disable-sandbox
# Build complete! (40.06 秒)

cd …/MPV && xcodebuild -scheme PlayerMPV -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/dd-ios-check OTHER_SWIFT_FLAGS=-disable-sandbox build
# ** BUILD SUCCEEDED **
```

> ⚠️ **第一条不算数**：那是 macOS 构建，而 macOS 上 `Libmpv` 被 `.when(platforms: [.iOS])` 排除，
> `MPVKernel` 又整份被 `#if canImport(Libmpv)` 圈住 ⇒ 那次 `Build complete` 只是
> **"一个空模块能 import"**，没有编译出任何 mpv 代码，也没有碰 xcframework（详见 §4.2）。
> 真正的验证是第二条 iOS 构建。这一点是本轮实测后才纠正的，之前误以为 macOS 那次也算证据。
>
> 不加 `OTHER_SWIFT_FLAGS=-disable-sandbox` 会撞 SwiftUI 宏的沙盒问题（环境已知，不是项目缺陷）。

## 三、三个结构性原因

| # | 原因 | 一句话 |
| --- | --- | --- |
| 1 | **适配器在子包里** | SPM 的 `url:` 依赖**只读仓库根清单**。根清单没有 `PlayerMPV` product ⇒ 外部永远拿不到 |
| 2 | **产物不进版本库** | 104 MB 被 gitignore ⇒ 任何 clone 下来都是残缺的，而 `binaryTarget(path:)` 要求文件真实存在 |
| 3 | **没有版本** | 0 个 tag ⇒ 无法按版本引；也没有 `binaryTarget(url:checksum:)` 需要的 zip + checksum |

---

## 四、两个必须知道的坑（都是这轮新测出来的）

### 4.1 `package:` 参数认的是**目录名**（identity），不是清单里的 `name`

```swift
// 实测报错
error: unknown package 'PlayerStack' in dependencies of target …
       valid packages are: 'playerlearning' (at '/Users/tango/Developments/playerlearning')
```

同理，依赖 `MPV/` 时 identity 是 **`MPV`**，不是 `PlayerMPV`。

**为什么这很要命**：一旦改成 `url:` 依赖，identity 会变成**仓库名**。
今天 Jove 侧写 `.product(name: "PlayerMPV", package: "MPV")` 能过，
换成 `url:` 之后同一个参数就会失效。**这不是笔误问题，是"引用形态变了 identity 就变了"。**

### 4.2 macOS 上是「编译得过、里面是空的」

```bash
/usr/libexec/PlistBuddy -c "Print :AvailableLibraries" …/Info.plist
# SupportedPlatform = ios            ← ios-arm64
# SupportedPlatform = ios (simulator) ← ios-arm64_x86_64-simulator
# （没有 macos）
```

而两份清单都写着 `platforms: [.iOS(.v17), .macOS(.v14)]`。链条是这样断的：

| 环 | 事实 |
| --- | --- |
| ① | `MPV/Package.swift` 里 `Libmpv` 用 `.when(platforms: [.iOS])` ⇒ macOS 不引入 |
| ② | `MPVKernel.swift` **整份文件**（L1–L956）被 `#if canImport(Libmpv)` 包住，其余 4 个文件也有 iOS 守卫 |
| ③ | macOS 上 `canImport(Libmpv)` 为 false ⇒ **整个适配器被编译掉** |

**结果不是"崩"，而是"空模块"**：macOS 上 `import PlayerMPV` 能过，但里面一个类型都没有。
这是最坏的一种失败 —— 不是报错，是让你以为有了。

⇒ `platforms:` 里的 `.macOS` 目前是**空头支票**。要么去掉，要么补 macOS 构建（成本不小）。
⇒ **推论**：§二证据 4 那条 `swift build` 的"成功"，其实什么也没验证到（见下方修正）。

## 五、欠缺清单

### 阻塞级（不解决，别人用不了）

| # | 项 | 现状 | 要做什么 |
| --- | --- | --- | --- |
| A1 | 根清单没有 `PlayerMPV` product | `Package.swift` 只有 `PlayerCore`/`PlayerUI` | 合并到根包，或根包转发 product |
| A2 | 产物不在版本库 | `git ls-files MPV/Library` = 0 · 104 MB | 换成 `binaryTarget(url:checksum:)`，走 Release 资产 |
| A3 | 没有 tag | `git tag` = 0 | 打 `v0.1.0`（首个可用版本） |
| A4 | 没有发布用 zip | `find . -name "*.zip"` 空 | 打两个 slice 的 zip + 算 `checksum` |
| A5 | `package:` 引用按目录名写死 | 见 §4.1 | 换 `url:` 时全部重算 |

### 影响级（能跑，但会咬人）

| # | 项 | 现状 | 建议 |
| --- | --- | --- | --- |
| B1 | `.macOS` 声明是空头支票 | 见 §4.2 | 去掉，或明确标注「仅 iOS 可跑」 |
| B2 | 隐私清单只在 `Demo/` | `find . -name "PrivacyInfo*"` 只 1 个 | 给 `PlayerMPV` 目标加一份，或在接入文档写明 App 侧要声明什么 |
| B3 | 公开面含内部机制 | `MPVSWSession`、`MPVHandleBox`、`MPVRenderProbe` 都是 `public` | 收成 `internal` 或 `@_spi`；对外只留 `MPVKernel` / `MPVRenderOutput` / `MPVRenderBridge` |
| B4 | 没有「抄了就能跑」的最小示例 | `Demo/` 是 xcodegen 工程，依赖两个 `path:` | 加一个 30 行的 `Examples/` snippet（装配三步） |

### 长期级

| # | 项 | 说明 |
| --- | --- | --- |
| C1 | 无版本策略 / 无 CHANGELOG | LGPL 要求「可重现」，需要「哪个版本对应哪份源码」的对照表 |
| C2 | 许可材料不跟包走 | `compliance/` 在仓库根，不在包内。分发时容易漏带 |

## 六、三条补齐路线

| | 甲 · 维持现状（只服务本机） | 乙 · **合并 + url 发布**（推荐） | 丙 · 独立发布仓库 |
| --- | --- | --- | --- |
| 做法 | 什么都不改，Jove 写 `path:` | `PlayerMPV` 并入根包；产物打 zip 挂 Release | 单开 `playerstack-dist` 仓库存产物与 tag |
| 工作量 | 0 | 中（改清单 + 打包 + 打 tag + 一次干净 clone 验证） | 大（双仓同步，容易漂） |
| Jove 能用 | 只在本机 | ✅ 任何人 | ✅ 任何人 |
| 满足 Jove `CONTEXT.md`「不用 path 本地包」 | ❌ | ✅ | ✅ |
| 104 MB 放哪 | 不解决 | GitHub Release 资产 | 独立仓库 Release |
| 长期风险 | 越拖越贵（身份、版本全缺） | 低 | 中（同步成本） |

**推荐乙**。理由：Jove 的既有规则是「不用 `path:` 本地包」，甲方案直接违反它；
丙方案要维护两套版本关系，而这个包的体积主要来自一个不常变的二进制，双仓收益不抵成本。

---

## 七、若走乙，最小发布清单（5 步，按顺序）

1. **合并**：把 `PlayerMPV` target 与 `Libmpv` 的 `binaryTarget` 挪进根 `Package.swift`，
   或保留子包但在根清单里补一个转发 product（前者简单，后者不用搬 104 MB）
2. **打包**：`ditto -c -k --keepParent Libmpv.xcframework Libmpv.xcframework.zip`，`swift package compute-checksum`
3. **发**：上传到 GitHub Release，`binaryTarget(name: "Libmpv", url: …, checksum: …)`
4. **打 tag**：`v0.1.0`，并在 `compliance/SOURCE.md` / `MODIFICATIONS.md` 里记「v0.1.0 对应哪个 commit」
5. **验**：**干净 clone → 换到 `url:` 依赖 → iOS 目标构建**。这三步缺一步都不算发布完成

> 第 5 步是唯一能证伪前面所有工作的动作。**没做过这一步，「可发布」就是推断，不是事实。**
