# P0-T5a · 技术验证报告（libmpv + MoltenVK 冒烟）

> **对应 ticket**：`P0-T5a`（由 `P0-T5` 拆出的第一步）
> **日期**：2026-10-13
> **目标**：回答「MoltenVK 在 iOS 上能不能用 / `wid` 嵌入能不能出画面」—— 这是 `P0-T5` 里唯一可能推翻「上架」前提的问题

> **证据**：`docs/assets/p0t5a/`（5 张截图）

## 一、结论先说

**`wid` 嵌入 + `vo=gpu-next` / `gpu-api=vulkan` / `gpu-context=moltenvk` 在 iOS 上可跑通，且真机可用。**

⇒ `P0-T5` 的**技术不确定性已消除**，剩余的 `P0-T5b`（自建动态 LGPL 产物）降级为**纯构建工程**，不再威胁「上架」这个前提。

顺带把 `docs/03` 的 **M0「路线成立」** 提前钉死了一大半：libmpv 不但在 iOS 上能跑，还能**播本地 mkv + 渲染 PGS 图形字幕 + 硬件解码**。

## 三、可用配置（后续 ticket 直接复用）

### 3.1 mpv 初始化序列

```swift
guard let handle = mpv_create() else { ... }
mpv_request_log_messages(handle, "info")
var layerPointer = Unmanaged.passUnretained(metalLayer).toOpaque()
mpv_set_option(handle, "wid", MPV_FORMAT_INT64, &layerPointer)
mpv_set_option_string(handle, "vo", "gpu-next")
mpv_set_option_string(handle, "gpu-api", "vulkan")
mpv_set_option_string(handle, "gpu-context", "moltenvk")
mpv_set_option_string(handle, "hwdec", "videotoolbox")
mpv_set_option_string(handle, "video-rotate", "no")
mpv_set_option_string(handle, "keep-open", "yes")
mpv_observe_property(handle, 0, "video-params/w", MPV_FORMAT_INT64)
mpv_observe_property(handle, 0, "video-params/h", MPV_FORMAT_INT64)
mpv_observe_property(handle, 0, "video-params/pixelformat", MPV_FORMAT_STRING)
mpv_observe_property(handle, 0, "time-pos", MPV_FORMAT_DOUBLE)
mpv_observe_property(handle, 0, "paused-for-cache", MPV_FORMAT_FLAG)
mpv_initialize(handle)
mpv_set_wakeup_callback(handle, { ctx in /* 转 UnsafeMutableRawPointer → 控制器 → readEvents() */ }, ...)
```

### 3.2 三条必须遵守的实施要点

1. **`MetalLayer` 必须重写两个 setter**（否则有已知故障）：
   - `drawableSize`：过滤 ≤1 的赋值 —— MoltenVK 会把它设成 1x1 强行完成 present，导致闪烁（mpv PR #13651）
   - `wantsExtendedDynamicRangeContent`：强制切主线程 —— 非主线程无法激活屏幕 EDR（影响后续 HDR 支持）
2. **Metal API Validation 必须关闭**（Xcode Scheme → Run → Diagnostics），否则播 HDR 会崩溃（MoltenVK issue #2226）。本 ticket 未测 HDR，此坑留待 Phase 2 验证。
3. **`mpv_command` 的参数类型**：Swift 里须构造 `[UnsafePointer<CChar>?]` 并追加 `nil` 结尾；直接传 `[UnsafeMutablePointer<CChar>?]` 会编译失败。

## 四、过程中解决的四个问题（都值得沉淀）

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | **签名 Team 字段搞错**：`〔证书成员 ID〕` 是证书的**成员 ID**（证书 OU 字段），**不是 Team ID** | 正确 Team 从 `defaults read com.apple.dt.Xcode DVTDeveloperAccountManagerAppleIDLists` 读 → 本机为 `〔个人 team〕`（个人）与 `〔公司 team〕`（公司） |
| 2 | **真机部署签名**：个人 Team 无现成描述文件 | 改用 `〔公司 team〕`，因其本机已有 **wildcard 描述文件**（`〔公司 team〕.*`）⇒ 复用，**不新建 App ID、不新增任何账号资源** |
| 3 | **`raw.githubusercontent.com` 在此网络极不稳定**：20.9 MB 的 mkv 两次被超时截断（只拿到 256 K） | 改用 **jsDelivr**：`https://cdn.jsdelivr.net/gh/mpvkit/video-test@master/resources/<file>` —— 1 分钟下完 20 M + 3 M |
| 4 | **SPM 下载量翻倍**：`.binaryTarget(url:)` 会被**全部**下载（GPL 与 LGPL 两套） | 无法避免（SPM 行为）。已确认**实际链接**的是 `MPVKit` product（→ `_MPVKit` → 非 GPL 的 `Libmpv`）✓ |
| 5 | **真机 launch 需设备解锁**：`FBSOpenApplicationErrorDomain error 7 Locked` | 用 `devicectl device process launch` **轮询重试**（每 3 秒，解锁瞬间即成功）；另注：`devicectl` **无** `--output`，截图参数是 `--destination` |
