## 三、许可证据链（本次核心）

### 3.1 产物自报许可

```
libavcodec    license: LGPL version 2.1 or later
libavdevice   license: LGPL version 2.1 or later
libavfilter   license: LGPL version 2.1 or later
libavformat   license: LGPL version 2.1 or later
libavutil     license: LGPL version 2.1 or later
libswresample license: LGPL version 2.1 or later
libswscale    license: LGPL version 2.1 or later
```

对比 `P0-T4` 在 MPVKit 预编译产物上看到的 `LGPL version 3 or later` —— **版本确实降下来了**。

### 3.2 「压回 2.1」的真正门槛（本次最重要的发现）

**第一次尝试（只去掉 `--enable-version3`）直接构建失败**：

```
gmp is version3 and --enable-version3 is not specified.
```

⇒ `--enable-version3` 只是**声明**；真正要求 v3 的是**被链进来的库**。顺错查清的传导链：

| 环节 | 事实 | 依据 |
| --- | --- | --- |
| `gmp` | LGPLv3+ / GPLv2+，在 FFmpeg 的 `EXTERNAL_LIBRARY_VERSION3_LIST` | `FFmpeg/configure` L2051-2060 |
| `gmp` 在 FFmpeg 里被用来做什么 | **仅 `libavformat/rtmpdh.c`（RTMP 的 Diffie-Hellman）** —— 与本地/HTTP 播放无关，且有内部回退实现 | `rtmpdh.c` L62 |
| **引入 gmp 的真正路径** | `--enable-gnutls` → **nettle**（同为 LGPLv3+/GPLv2+）→ **gmp** | mpvkit 构建脚本的 LDFLAGS |
| **mpv 自己要不要 gnutls** | **不要** —— mpv `v0.41.0` 的 `meson.build` 里 gnutls / openssl / gmp / smbclient **零匹配**，TLS 全走 FFmpeg | mpv `meson.build` |
| **替代方案** | FFmpeg 自带 **SecureTransport** = Apple 系统 TLS（`Security.framework`），文档标注 `[autodetect]`，且与 gnutls **互斥** | `FFmpeg/configure` L342 / L4108 |
| `libsmbclient` | FFmpeg 归在 `EXTERNAL_LIBRARY_GPLV3_LIST`；本构建从未 `--enable-libsmbclient` ⇒ 未链入 | `configure` L2062-2064 |

### 3.3 链入的静态库清单（无 gnutls / nettle / gmp）

从本次构建日志的 libmpv 最终链接行提取 —— **21 个静态库**：

```
libMoltenVK.a  libass.a  libavcodec.a  libavdevice.a  libavfilter.a  libavformat.a
libavutil.a  libbluray.a  libdav1d.a  libdovi.a  libfreetype.a  libfribidi.a
libharfbuzz.a  liblcms2.a  libplacebo.a  libshaderc_combined.a  libswresample.a
libswscale.a  libuavs3d.a  libuchardet.a  libunibreak.a
```

其中 **gnutls / nettle / gmp / hogweed 命中数 = 0**。

### 3.4 误报澄清（避免以后重复排查）

对产物 `strings` 扫描时 `gnutls`/`gmp`/`x264`/`vdpau` 有非零命中，**全部为误报**，符号级已证伪：

| 命中 | 原文 | 判定 |
| --- | --- | --- |
| `gnutls` ×1 | `https or dtls protocol not found, recompile FFmpeg with openssl, gnutls or securetransport enabled.` | FFmpeg 的**错误提示文案** |
| `gmp` ×4 | base64 数据块与 MIME 串（`...pgmpu:data:...`、`@DFINTWZagkou…`） | 随机字节巧合 |
| `x264` ×7 | `vd-lavc-assume-old-x264`、`x264_build`、`x264 - core %d` | mpv 选项名 + h264 解码器读 SEI 里编码器版本的字符串 |
| `vdpau` ×14 | **产物自带的 configure 行**（含 `--disable-vdpau`）+ `glVDPAURegisterVideoSurfaceNV` | 自证行 + OpenGL 扩展名 |

**决定性证据**：`nm -u` 的 920 个导入符号里，gnutls / nettle / gmp / x264 / vdpau / smbclient **零命中**。

> **方法论沉淀**：**`strings` 命中不可作为链接证据，`nm -u`（未定义符号）才是。** 这条避免以后每次都被同一批误报干扰一遍。

> ### ⚠️ 2026-10-16 标注（`P0-T5c` 交付后加，原文保留）
>
> **第 1 项已验**（补做于 2026-10-16，报告 [`docs/18`](18-P0-T5c-HTTPS行为验证.md)），
> 而结论与"回退路径"那段设想的**不一样**：
>
> - **这个产物的 HTTPS 不校验证书** —— 不受信任、甚至名字不匹配的证书，**真机与模拟器都照播**；
>   宿主 `curl`（同一个 SecureTransport 后端）则拒绝。
> - 根因：`tls_verify` 的**默认值虽然是 1**（`libavformat/tls.h:93`），但 `tls_securetransport.c`
>   只在 **`ca_file != nil`** 时才打开 `kSSLSessionOptionBreakOnServerAuth` ——
>   而本构建 **`HAVE_SECITEMIMPORT 0`**（`config.h` + `nm -u` 里 `SecItemImport` 0 命中）⇒
>   **CA 文件永远加载不了**（实测：给了 `tls-ca-file` 后连证书完全正确的那台也打不开）。
> - ⇒ **不存在会校验的配置**。第 2 项那条"一行开关换 `--enable-openssl`"**换不掉 "要随包 CA 列表" 这件事**
>   （OpenSSL 在 iOS 上也没有系统兜底路径；`/etc/ssl/cert.pem` 在本机 iOS 27 运行时里已不存在），
>   而且它会把信任模型换成"我们维护的根列表"（**用户自签不生效**）。
> - **修复路径与代价对比**见 `docs/18` §五；**推荐给 FFmpeg 打一个小补丁**，
>   让 `SecTrustEvaluate` 真正跑起来并用**系统锚点**（零随包资源、与 iOS 惯例一致）。修复**尚未动**。
