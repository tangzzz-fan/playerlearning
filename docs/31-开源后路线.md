# 31 · 开源之后：现状、下一步、往哪发展

> 背景：仓库已从 private 改为 **public**（2026-10-17）。
> 本文回答三件事：**现在还差什么**、**下一步按什么顺序做**、**这个项目往哪发展**。
> 每条事实都带可核对命令；没验过的写「未验证」，不写成结论。

---

## 一、一句话结论

**产物已经真的是"可下载、可构建"了，但对外引用仍不成立** —— 因为 `v0.1.0` 那份清单是 `path:` 形态。
差的是**一个新 tag**，不是新代码。

```bash
# v0.1.0 标签里的清单（注意第 39 行）
git show v0.1.0:Package.swift | grep -n "binaryTarget" -A2
# 39:        .binaryTarget(name: "Libmpv", path: "MPV/Library/Libmpv.xcframework")
```

⇒ 任何人写 `.package(url: …, from: "0.1.0")` 都会读到这份 `path:` 清单，然后在他自己的机器上找 `MPV/Library`，找不到就失败。
**主分支已经改成 `url:` 形态并实测通过，但那版还没打标签。**

## 三、往哪发展：三条路线

项目现在有两个已验证的资产：

- **能播的引擎** —— 协议 + 状态机 + 386 条测试，`PlayerCore` 零 UI 依赖
- **帧可编程** —— render API 软件后端，帧落进我们的 `CVPixelBuffer`，真机 4K 按上屏 11.51 ms

| 路线 | 是什么 | 对手 | 判断 |
| --- | --- | --- | --- |
| **A 通用播放内核** | 做一个"什么都能播"的 Swift 播放库 | KSPlayer / VLCKit / MobileVLCKit 已经把这件事做到极致 | ❌ 差异化最弱。别人凭什么换过来？ |
| **B 可编程帧引擎** | 卖点不是"能播"，而是**帧在你手里**：自绘字幕、滤镜链、2D→3D、AI 推理都能插 | **现在没有成熟的 Swift 方案**。要么用 AVFoundation（格式受限），要么自己啃 libmpv C API | ✅ 唯一有差异化的位置 |
| **C Jove 内部组件** | 不追求对外，只服务一个产品 | — | ✅ 成本最低，但拿不到外部反馈 |

**推荐 B + C 并行，而不是二选一**：C 是 B 的**第一个真实消费者**。
开源库最容易犯的错是"闭门设计 API" —— 而 Jove 在线浏览 + 2D→3D 正好会把 API 逼出来：哪些必须公开、哪些该藏在内部、哪些抽象是多余的，接一次就全暴露了。

一句话：**用 Jove 当 dogfooding，把 B 的 API 磨出来。**

### 四·补 · 改名的影响面（实测）

`gh repo rename playerstack` 之后，下面这几处**必须**跟着改，漏一处就构建不了：

| 影响点 | 原值 → 新值 | 为什么 |
| --- | --- | --- |
| `Package.swift` 的 `binaryTarget` URL | `…/playerlearning/releases/download/v0.1.0/…` → `…/playerstack/releases/download/v0.1.1/…` | URL 里含仓库名 |
| 消费方的 `package:` 参数 | `playerlearning` → **`playerstack`** | **identity 取自仓库名**，`path:` 与 `url:` 都一样 |
| `Package.swift` 的 `name:` | 保持 `PlayerStack` | manifest 的 displayName，不必跟仓库名一致 |

**不受影响**：product 名（`PlayerCore` / `PlayerUI` / `PlayerMPV`）、target path、Demo 的 XcodeGen 配置。
**旧名会 301 重定向**，但那只是过渡，清单里一律写新名。

⚠️ 有一条与"`path:` 换 `url:`"不同、很容易搞混：**换形态不动 identity，改名才动 identity。**
上次实测确认过"换 `url:` 不用改 `package:`"，于是很容易顺手认为改名也不用改 —— 这是错的两件事。

**T1 / T2 / T3 是阶段一，可以今天做完。** 之后的顺序有讲究：T5 会改公开面 ⇒ 必须在 T8 之前，否则 Jove 写完还要跟着改。

## 五、两个不能省的动作（为什么）

### T1 为什么不能省：版次印错了，得再印一版

ELI5：`v0.1.0` 像一本已经印出去的书，书里写的取货方式是"去我家的仓库自取"（`path:`）。我们把**原稿**改成了"快递寄给你"（`url:`），但**已经印出去的那一版没变** —— 别人手里那本还是旧地址。

所以 tag 不是"发布仪式"，是**内容的快照**。改了清单就必须新开一个快照。

### T2 为什么不能省：public ≠ 可使用

ELI5：把仓库改成 public，等于**把门打开让别人进来参观**；而 LICENSE 是**门口那块牌子**，写着"这些东西你可以拿去用，条件是……"。没有牌子，法律默认是「保留所有权利」—— 别人复制走反而有法律风险，正经公司**不敢**用。

而且这里有一层反差值得记：我们为 **LGPL 合规**准备了 `compliance/` 五件套（源码 / 许可文本 / 可替换性 / 修改声明），却**没有给自己那份代码写许可**。一个开源项目最讽刺的状态莫过于此。

要决定的是：**用自己的代码用哪个许可**。mpv 是 LGPL-2.1，我们的封装层是独立作品，不受它传染 —— 所以可以选 MIT（最宽松，利于传播）或 Apache-2.0（带专利授权，与 LGPL-2.1 有已知摩擦，见 `compliance/README.md` §一）。

## 六、敏感信息（实测扫描结果）

```bash
git grep -n -I -E "UKXWZ3FS84|3GMJYX32U9|192\.168\.[0-9]+\.[0-9]+|TIANJU DIHE|Apple (Distribution|Development):" \
  -- . ':!docs/assets'
```

命中的四类：

| 类别 | 具体值 | 出现在 | 风险 |
| --- | --- | --- | --- |
| 个人 Team ID | `UKXWZ3FS84` | `Demo/project.yml` · `Demo/ExportOptions.plist` · `README` · `docs/03` | 低（不是密钥），但**写死会让别人 clone 后签名失败** |
| 公司 Team ID + 公司全名 | `3GMJYX32U9` · `TIANJU DIHE (SUZHOU) DATA CO., LTD.` | `docs/02` · `docs/03` · `docs/04` | 中 —— 企业身份与上架账号关联，配合社工有想象空间 |
| 证书主体与编号 | `zhenzhi Tang (7H6TJ2PN25)` · `Tang Tango (WU37464V73)` | `docs/03` · `docs/04` | 低（Apple 会对外显示），但没必要公开 |
| 局域网拓扑 | `192.168.2.217:8765` / `:8554` | `README` · `docs/03` · `docs/12` · `docs/13` · `MPV/Tests/.../StreamProbePlanTests.swift` | 低（仅局域网可达），但暴露了测试环境结构 |

**建议的处置分两层**：

1. **工作树**（必做）：`Demo/project.yml` 的 `DEVELOPMENT_TEAM` 改成空值或 `$(DEVELOPMENT_TEAM)` 占位，README 里说明"填你自己的 team"；文档里的 IP 与 Team ID 换成 `<你的 team>` / `<局域网 IP>`。
2. **历史**（可选，但只有现在能做）：`git filter-repo --replace-text` 重写 + force push。0 fork 的窗口一旦关掉就再没有这个机会。

⚠️ 别把这件事当成"洁癖"。`Demo/project.yml` 里那个写死的 Team ID 是**真实的可移植性缺陷** —— 任何外部使用者按 README 跑 Demo，都会撞签名失败。

### 执行结果（2026-10-17）

工作树已清：**85 处 · 16 个文件**，映射见 `1b71b5d` 的提交说明。复跑扫描应为 0
（`192.168.x.x` 是既有占位符，不在口径内）。

`Demo/project.yml` 不是简单替换：改成 `DEVELOPMENT_TEAM: ""`（走自动签名）并加注释，
说明"填你自己的 Team ID"与"命令行传 `DEVELOPMENT_TEAM=`"两种做法。

**没有重写 git 历史** —— 这一条与 §七 的 D2 建议相反，理由是执行时才量出来的：

| 事实 | 数据 |
| --- | --- |
| `--replace-text` 会改名的 commit | 含这些串的文件（`docs/02·03·04`、`Demo/project.yml`…）被多次改过，父链一变 ⇒ 基本等于全历史重写 |
| 会被打断的引用 | docs / README / compliance 里共 **27 处 commit hash 引用**（证据链的一部分） |
| 泄漏物是否可用 | 都不是凭据：Team ID 无法用于盗用（需证书私钥），内网地址仅在局域网可达 |
| 工具 | `git-filter-repo` 本机未安装 |

⇒ **证据链的价值 > 隐藏这几项的收益**。历史里仍有，将来真要处理可以单独做一次（脚本可复现）。

## 九、一句话记住

**发布不是"改个 public"，是把三件东西同时对齐：快照（tag）、许可（LICENSE）、受众（README）。**
前两件是硬门槛，第三件决定别人会不会留下来。
