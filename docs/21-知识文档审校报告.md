## 三、修正详解（4 组 · 已落盘）

### A ❌ 领域级错误：`libplacebo` 不是"只会说 Vulkan"

**原文**（`K4` 结论框 / §2 / 术语表）："libplacebo 只会说 Vulkan，苹果只听得懂 Metal，中间必须有翻译"，
并把"必须绕这一圈"写成 `libplacebo` 的属性。

**实测（产物符号）**：

```bash
strings MPV/Library/Libmpv.xcframework/ios-arm64/Libmpv.framework/Libmpv \
  | grep -oE 'pl_(opengl|vulkan)[a-z_]*' | sort -u
# pl_opengl_create · pl_opengl_create_swapchain · pl_opengl_swapchain_update_fb
# pl_opengl_unwrap · pl_opengl_wrap          ← OpenGL 后端，五个符号都在
# pl_vulkan_choose_device · pl_vulkan_create · pl_vulkan_create_swapchain · pl_vulkan_destroy · pl_vulkan_hold_ex
```

**为什么这条错得要紧**：它还**与同篇 §2 自相矛盾**（那里写着"mpv 支持 `gpu-api=opengl`"）。
读者会由此得出"**别无选择**"的结论 —— 而实际存在不绕 MoltenVK 的路（让 libplacebo 走它自己的 GL 后端）。

**改法**：绕路重述为**我们这组选项**（`gpu-api=vulkan` + `gpu-context=moltenvk`）的代价，
并把**反例配置**（`gpu-api=opengl`）与"为什么不选它（画质取舍）"一起写清。
一般化的教训 → [`P-083`](PITFALLS.md)：写"某组件只会/必须 X"之前，先问"这是我们选的，还是它本身的限制？"

### B ⚠️ 判据不可复现：`moltenvk|mvk → 128`

**原文**（`K4` §3.3）：`strings Libmpv | grep -icE "moltenvk|mvk"  # → 128`

**实测（同一份产物，三种写法）**：

| 命令 | 结果 |
| --- | --- |
| `grep -c -i "moltenvk"` | **20**（用它） |
| `grep -c -E "moltenvk\|mvk"` | **28** |
| `grep -c -iE "moltenvk\|mvk"` | **840** ← `-i` 下的子串匹配把无关字符串全算进来 |

**根因**：**只留了数字、没留口径** —— 计数型判据里的"是否大小写敏感 / 是否子串匹配 / 匹配什么范围"
**本身就是判据的一部分**。⇒ 改法：三条并列命令 + 三个数字 + 一句"用哪一个"。
一般化的教训 → [`P-082`](PITFALLS.md)。

### C ⚠️ 口径过强：`api_type` 的四个"后端"

**原文**（`K6` §3.2）：把 `opengl` / `software` / `vulkan` / `d3d11` 四个词都列为
render API 的 `api_type`"实测"结果（从产物字符串读出）。

**问题**：这四个词在产物里**确实都能搜到**，但"**字符串里出现过**"≠"**它是这个选项的取值**"。
mpv 文档明确支持的 render API 后端只有 **`opengl` 与 `sw`**；`vulkan` / `d3d11` 的字符串来自别的子系统
（hwdec / vo 之类）。把二者混在一张表里，会让读者误以为"vulkan 后端可用"。

**改法**：表格拆成两档（✅ 文档明确支持 / ⚠️ 存疑），并把"未实测"的标注保留在 §7 待验清单里。

### D ⚠️ 完备性缺口（2 处，已补）

| 缺口 | 为什么算缺口 | 补法 |
| --- | --- | --- |
| **音频那一路** | 8 篇整体是"视频视角"：K1 只提了一句 `libswresample`，K3 只有一处 `音频 48000/48000 Hz` 观测。**"分辨音视频知识"却缺掉一半**，而且"音画同步"这件事的机理（音频即时钟）无处可读 | `K3` 新增 **§9**：前四站共用 → ④ 之后分道（`vo` vs **AO**）· PCM / 采样率 / 重采样四个词 · **为什么两个采样率要分别观测** · **为什么没有 AO 选项** · 产物里 `AVFAudio`/`AudioToolbox` 就是这条链的落点；并补一条**未实测**推论（纯音频没有 `vo-configured` ⇒ 起播判据失效） |
| **低延迟协议变体** | K5 通篇在讲"延迟取舍"，协议谱系却只有常规 HLS/DASH（3–30 s）——**低延迟那一档（LL-HLS / LL-DASH）恰恰是这个取舍的关键补集** | `K5` §2 补一行 + 一段口径：低延迟不做协议替换，而是**分片切更碎 + partial segment**，换来请求数变多；走**同一个 demuxer**，能否真降下来取决于服务端（标未实测） |
