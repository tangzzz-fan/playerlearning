### ⚠️ 「出声」的证据口径（必须写明，不许含糊）

音频链路分成**两段**，「有音轨」与「真在出声」不是一回事，所以内核也分两个信号观察：

| 信号 | mpv 属性 | 含义 |
| --- | --- | --- |
| `decoderSampleRate` | `audio-params/samplerate` | **解码端**：确实有一条音轨在被解码 |
| `outputSampleRate` | `audio-out-params/samplerate` | **输出端**：音频输出（AO）已建立并拿到采样率 |

实测两段都成立（`44100 → 0` 然后 `44100 → 44100`），所以：

- ✅ **证到了**：文件有音轨 · mpv 在解码它 · **音频输出已建立**（声音进了 AO）
- ❌ **没证到**：扬声器/耳机真的发出声音。那需要**录音或人耳**，命令行证明不了 —— 这一句必须留着

## 二、性能基线（首轮实测，**作为后续回归的参照值**）

环境：iPhone 18 Pro 模拟器（iOS 27.0 运行时）· Debug 构建 · libmpv 自建动态 LGPL-2.1 · `vo=gpu-next` + `gpu-context=moltenvk`
素材：640×360 / 5.00 s H.264 **+ AAC 44100 Hz 单声道**

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| 样例生成（一次性，落盘缓存） | **1.4 s** | 逐帧编码 + AAC 编码 + 无重编码封装；幂等，第二次为 0 |
| `loadfile` → `readyToPlay` | **1.93 s** | ⚠️ 见下方「音轨带来的代价」 |
| → 首次上报画面尺寸 | **+38 ms** | `3.324 → 3.362` |
| → 音频输出建立 | `4.388`（`playing` 之后 **1.04 s**） | AO（CoreAudio）初始化的耗时 |
| **首屏（`loadfile` → 画面尺寸）** | **1.97 s** | ⚠️ 见下方「音轨带来的代价」 |
| **播放速率** | **1.19x**（5.00 s 媒体 / 5.95 s 墙钟） | ⚠️ 见下方「音轨带来的代价」 |
| **缓冲次数**（`bufferingChanged(true)`） | **0** | 本地文件，全程未进缓冲 |
| **内存峰值**（`phys_footprint`） | **54.5 MB** | 启动 20.3 → 播放中 ~50.0 → 峰值 54.5，**有回落** |
| 竞态：`decoderSampleRate` 先到、`outputSampleRate` 后到 | 相差 28 ms | 证明两个信号确实独立，合成一个 Bool 就会撒谎 |

### ⚠️ 音轨带来的代价（如实记，别把它藏起来）

同一份代码，**只加了一条音轨**，两个指标显著变差：

| 指标 | 无音轨（`P2-T11`） | 有音轨（`P2-T12`） | 变化 |
| --- | --- | --- | --- |
| 首屏 | **60 ms** | **1.97 s** | **慢约 33 倍** |
| 播放速率 | 1.02x | **1.19x** | 慢约 17% |

**归因（只说到有证据的程度）**：延迟几乎全部落在 `loadfile → FILE_LOADED` 这段，
且紧随其后的是 AO 初始化 ⇒ **主要怀疑模拟器的 CoreAudio 输出初始化**（模拟器音频栈是出了名的慢）。
播放速率变慢同理：模拟器音频输出的节拍不精确，媒体时钟被它拖住。

**这两条必须在真机上复测才能定案**（真机 CoreAudio 是原生路径）。**在此之前不要据此优化代码** ——
优化一个模拟器假象是纯粹的浪费。

### 量法（方法决定数据能不能复现）

| 指标 | 怎么量的 |
| --- | --- |
| 时间线 | Demo 的 `-traceUpdates` 把每条 `PlayerControllerUpdate` 打到 **stderr**（无缓冲），带**相对进程启动的单调秒数** |
| 内存 | Demo 内部读 `task_info(TASK_VM_INFO).phys_footprint`（与 Xcode 内存仪表同源），每秒采样 |
| 为什么不从外部量 | ⚠️ `/bin/ps` 在本机被拒（`operation not permitted`），**且叠加 `dangerouslyDisableSandbox` 后仍被拒** ⇒ 限制不在沙盒层，只能从进程内部读 |

**原始 trace**：[`docs/assets/p2t11/demo-trace.log`](assets/p2t11/demo-trace.log)（无音轨那轮；有音轨那轮的 trace 见本文件 §二 的引用数字）。

### 门槛值（后续回归判据）

| 指标 | 门槛 | 依据 |
| --- | --- | --- |
| 本地文件缓冲次数 | **= 0** | 本地文件不该进缓冲；出现即回归 |

## 三、`G2` 怎么固化进 `gate.sh`

`gate.sh` 共 **7 步**，其中 **`[6/7]` 就是 G2** —— 它做的是**真跑一遍**：

```
xcodegen generate → xcodebuild build（Demo）
  → simctl install → simctl launch --console … -autoLoadSample -traceUpdates
  → 解析 stderr 的 [trace] 行，断言四件都在：
      ① stateChanged(playing)
      ② videoSizeChanged((640.0, 360.0))
      ③ audioChanged(… decoderSampleRate: 44100, outputSampleRate: 44100)   ← 出声
      ④ stateChanged(finished)
  → 截图存档到 docs/assets/p2t11/gate-screenshot.png
```

**为什么必须单列**：`[5/7]` 的 MPV 包测试是 **headless**（`vo=null`），证明不了"真画面能出来"——
`wid` + MoltenVK + `CAMetalLayer` 这条接线**只有把 App 真跑起来才覆盖**。

**三级网**（`P2` 最有价值的结构性收获）：

| 层 | 覆盖面 | 谁能发现 |
| --- | --- | --- |
| 根包单测 + 变异（63 个变异体） | 纯逻辑：状态机 / 时间模型 / 音频状态 / 装配层 | 改逻辑就红 |
| `MPV` 包行为测试（11 条，headless） | 内核行为：事件序列 / 属性观测 / 原因分派 | 改内核就红 |
| **`G2` 端到端（`[6/7]` 真跑 App）** | **接线：`wid` + MoltenVK + `CAMetalLayer` + CoreAudio** | 改接线就红 |
