## 二、性能基线（首轮实测，**作为后续回归的参照值**）

环境：iPhone 18 Pro 模拟器（iOS 27.0 运行时）· Debug 构建 · libmpv 自建动态 LGPL-2.1 · `vo=gpu-next` + `gpu-context=moltenvk`

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| **首屏耗时**（`loadfile` 发出 → 上报画面尺寸） | **60 ms** | `t=0.156` → `t=0.216`（相对进程启动） |
| 其中：`loadfile` → `readyToPlay` | 55 ms | `0.156` → `0.211` |
| 其中：`readyToPlay` → `videoSizeChanged` | **5 ms** | `0.211` → `0.216` |
| **播放速率** | **1.02x 实时** | 媒体时间 5.00 s / 墙钟 5.25 s（`0.156 → 5.406`）⇒ **无掉帧** |
| **缓冲次数**（`bufferingChanged(true)`） | **0** | 本地文件，全程未进缓冲 |
| **内存峰值**（`phys_footprint`） | **49.1 MB** | 启动 20.8 MB → 峰值 49.1 MB（约 `t=3.3 s`）→ 稳态 45.5 MB |
| 内存是否回落 | ✅ 回落至 45.5 MB | 峰值过后未持续增长，未见明显泄漏 |

**量法**（重要：方法决定了数据能不能复现）：

| 指标 | 怎么量的 |
| --- | --- |
| 时间线 | Demo 的 `-traceUpdates` 把每条 `PlayerControllerUpdate` 打到 **stderr**，带**相对进程启动的单调秒数** |
| 内存 | Demo 内部读 `task_info(TASK_VM_INFO).phys_footprint`（Xcode 内存仪表同源），每秒采样一次 |
| 为什么不从外部量 | ⚠️ `/bin/ps` 在本会话被沙盒拒绝（`operation not permitted`）⇒ **只能从进程内部读**。这也让数据不依赖环境权限 |

**原始 trace**：[`docs/assets/p2t11/demo-trace.log`](assets/p2t11/demo-trace.log)（含 MoltenVK 启动日志与全部 `[trace]` / `[mem]` 行）。

**门槛值**（后续回归的判据，取实测值的宽裕倍数）：

| 指标 | 门槛 | 依据 |
| --- | --- | --- |
| 首屏耗时 | **≤ 300 ms** | 实测 60 ms，留 5 倍余量（模拟器比真机慢，真机会更好） |
| 缓冲次数（本地文件） | **= 0** | 本地文件不该进缓冲；出现即视为回归 |
| 内存峰值（640×360） | **≤ 120 MB** | 实测 49.1 MB，留 2.4 倍余量（含解码器与 MoltenVK 的固定开销） |

## 三、`G2` 怎么固化进 `gate.sh`

`gate.sh` 由 6 步扩为 **7 步**，新增 **`[6/7] G2 端到端`** —— 它做的是**真跑一遍**：

```
xcodegen generate → xcodebuild build（Demo）
  → simctl install → simctl launch --console … -autoLoadSample -traceUpdates
  → 解析 stderr 的 [trace] 行，断言：
      ① 出现 stateChanged(preparing / readyToPlay / playing)
      ② 出现 videoSizeChanged(640×360)
      ③ 出现 stateChanged(finished)      ← 播完必须报（P-039 的回归网）
      ④ currentTime 推进到 > 4.5 s        ← 证明真的在放，不是只加载
  → 截图存档
```

**为什么必须端到端这一条**：`[5/7]` 的 MPV 包测试是 **headless**（`vo=null`），
它证明不了"真画面能出来"—— 那条路径涉及 `wid` + MoltenVK + `CAMetalLayer`，
**只有把 App 真跑起来才能覆盖**。这三层正好是三级网：

| 层 | 覆盖 | 谁能发现 |
| --- | --- | --- |
| 根包单测 + 变异 | 纯逻辑（状态机 / 时间模型 / 装配层） | 改逻辑就红 |
| `MPV` 包行为测试（headless） | 内核行为（事件序列 / 属性观测 / 原因分派） | 改内核就红 |
| **`G2` 端到端（有画面）** | **链路接线（`wid` / MoltenVK / 渲染表面）** | 改接线就红 |

## 四、未覆盖项与风险（如实记）

| # | 项 | 现状 | 补法 / 何时补 |
| --- | --- | --- | --- |
| 1 | **出声** | ❌ 无证据。样例片段无音轨，模拟器音频也未验证 | 给 `SampleClipWriter` 加一条 AAC 音轨（`AVAssetWriterInput(mediaType: .audio)`）；属 M3 前的必要项 |
| 2 | **真机** | ⚠️ 本轮只在**模拟器**验证。`P0-T5a/T5b` 证过真机出画，但那时的接线与现在不同（现在是包化的 `MPVKernel` + `PlayerController`） | 真机复跑一次 `G2`；`docs/03` 的 G2 口径是"真机**或**模拟器（视 G0 结论）" |
| 3 | **性能只在模拟器** | ⚠️ 模拟器的 MoltenVK 走 CPU 后端，真机会明显更好 | 门槛值先按模拟器定；真机数据出来后再校准 |
| 4 | **字幕与 mpv OSD** | ⚠️ 未涉及。`wid` 嵌入时 mpv 会把字幕画在最上层，会与自建 UI 打架 | 已知取舍（`docs/02` §4 风险 3），**P3/P4** 处理 |
| 5 | **Demo 只覆盖单文件** | ⚠️ 多音轨、字幕轨、网络流均未覆盖 | `P4`（字幕/轨道）、`P5`（网络点播） |

## 六、对后续阶段的两条直接结论

1. **接线层面没有暗礁了**：`wid` + MoltenVK + `CAMetalLayer` 这条链路已经在自己的代码里跑通，
   不需要再依赖 `spike/` 的样板。`spike/` 从此只是**历史证据**，不再承担"实现基线"的角色。
2. **`M2 能看片` 达成**，但"能顺手用"（`M3`）还缺三块：**UI 5 件套**（P3）、**字幕**（P4）、
   **音轨**（本轮欠的账）。按范围锚点，**这三块之外的需求一律后排**。
