## 三、`G1` 之外，这条最值得记：集成测试抓到了单元测试抓不到的东西

写下第一条集成测试时 **8/8 全崩**，证据集中且明确：

```
不应出现被拒的状态：[.readyToPlay, .playing, .paused, .playing]
```

**根因**：`FakeKernel.load()` **跳过了 `.preparing`**，直接发 `idle → readyToPlay`；状态机的迁移表（正确地）只允许 `idle → preparing`。

**关键点**：**两边的单元测试各自都过** —— 它们测的是**自己的内部一致性**，没有任何一条在测**两者的接口约定**。

**处置**：**修 fake 让它保真**（`load` 先发 `.preparing`），**而非放宽状态机** —— 放宽会永久掩盖这类序列缺陷；而真内核本来就是 `load → preparing → readyToPlay`。

⇒ 沉淀为 [`PITFALLS`](PITFALLS.md) `P-018`。**结论：单元测试全绿 ≠ 部件能组合；测试替身要保真到状态序列，不只是方法签名。**
